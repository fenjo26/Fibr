# Ретранслятор в России

Иногда в России недоступен **сам IP основного сервера**. Провайдеры блокируют целые подсети зарубежных хостеров (Timeweb Cloud NL, Hetzner, DigitalOcean, OVH и т.п.). Признак простой: у пользователя без VPN в браузере не открывается даже кабинет (`ERR_CONNECTION_TIMED_OUT`), хотя Википедия и другие сайты открываются. Маскировка протокола тут не поможет: соединение с этим IP не устанавливается вообще.

Ретранслятор решает это так: пользователь подключается к **российскому IP**, а маленький VPS в России просто пересылает трафик на основной сервер.

```
телефон в России ──► ретранслятор (VPS в РФ) ──► основной сервер Fibr (за границей) ──► интернет
                     nginx, только пересылка        Caddy / xray / WireGuard / AmneziaWG
```

- **Ретранслятор ничего не расшифровывает.** VLESS идёт по TLS с сертификатом вашего домена до Caddy на основном сервере. WireGuard и AmneziaWG зашифрованы от телефона до основного сервера. На российском VPS нет ни ключей, ни логов трафика.
- **Пересылаются порты:** `443/tcp` (VLESS через XHTTP), `8443/tcp` (VLESS + Reality, запасной), `51820/udp` (WireGuard), `51821/udp` (AmneziaWG).
- **Клиентам ничего пересоздавать не нужно.** Ключи те же, меняется только адрес в конфиге или ссылке. В кабинете появляется переключатель «🇷🇺 Я в России — подключать через ретранслятор».

## Что понадобится

- Основной сервер Fibr уже работает (домен, кабинет, VLESS на 443).
- **VPS в России**: 1 ядро, 1 ГБ RAM, Ubuntu 22.04/24.04 или Debian 12. Подойдут Timeweb Cloud (Москва, Санкт-Петербург), Selectel, Yandex Cloud, VK Cloud, reg.ru и другие. Нужен **чистый** сервер: порт 443 на нём должен быть свободен.
- IP основного сервера (на нём: `curl -4 -s ifconfig.me`).

## Шаг 1. Проверить, что российский VPS видит основной сервер

На российском VPS:

```bash
curl -sk -o /dev/null -w "%{http_code}\n" --resolve vpn.example.com:443:IP_ОСНОВНОГО https://vpn.example.com/cabinet/
```

Если пришёл `200`, связь есть. Если таймаут, значит, этот российский хостер тоже не пускает к вашему серверу. Возьмите VPS у другого хостера или в другом городе.

## Шаг 2. Поставить ретранслятор (одна команда)

На российском VPS под root:

```bash
curl -fsSL https://raw.githubusercontent.com/fenjo26/Fibr/main/relay/install.sh -o relay.sh
bash relay.sh --upstream IP_ОСНОВНОГО_СЕРВЕРА
```

Если GitHub с российского VPS не открывается, скопируйте файл `relay/install.sh` из репозитория любым способом (`scp`, вставить в `nano`) и запустите так же.

Установщик:

1. ставит `nginx` с модулем `stream` из пакетов Ubuntu/Debian (без Docker: Docker Hub из России часто недоступен);
2. пишет `/etc/nginx/fibr-relay.conf` с пересылкой портов и подключает его в `nginx.conf`;
3. открывает порты в `ufw`, если он включён;
4. проверяет, что основной сервер доступен, и печатает IP ретранслятора.

Нестандартные порты на основном сервере задаются флагами: `--wg-port`, `--awg-port`, `--xray-port`. Посмотреть конфиг без установки: `--print-config`. Удалить ретранслятор: `bash relay.sh --remove`.

Если в панели хостера есть свой файрвол, откройте там `443/tcp`, `8443/tcp`, `51820/udp`, `51821/udp`.

## Шаг 3. Включить ретранслятор на основном сервере

На **основном** сервере:

```bash
echo "FIBR_RELAY_HOST=IP_РЕТРАНСЛЯТОРА" >> /opt/fibr/install/.env
cd /opt/fibr/install && docker compose up -d
```

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `FIBR_RELAY_HOST` | пусто | IP (или домен) ретранслятора; пусто = ретранслятора нет |
| `FIBR_RELAY_DEFAULT` | `true` | выдавать конфиги через ретранслятор, если пользователь не выбрал иначе |

## Шаг 4. Пользователям: взять конфиг заново

В кабинете и мини-аппе над списком устройств появляется переключатель **«🇷🇺 Я в России — подключать через ретранслятор»**. По умолчанию он включён (`FIBR_RELAY_DEFAULT=true`), выбор запоминается в браузере.

- Включён: QR, «Скачать файл», «Конфиг», «Отправить в Telegram» выдают конфиг с адресом ретранслятора.
- Выключен: напрямую на основной сервер (для тех, кто не в России: так быстрее).

После переключения нужно **заново** отсканировать QR или скачать файл: старый конфиг указывает на прежний адрес. Ключи устройства не меняются.

Бот (`/new`, `/vless`, `/amnezia`) и быстрое подключение (join-коды, ТВ) выдают конфиги по умолчанию сервера (`FIBR_RELAY_DEFAULT`). В API тот же выбор задаётся параметром `?via=relay` или `?via=direct` у `/api/me/devices/{id}/config`, `qr.png`, `send` и `/api/join/{code}`.

Как выглядит VLESS-ссылка через ретранслятор: адрес российский, а `sni` и `host` остаются вашим доменом, поэтому TLS проверяется настоящим сертификатом:

```
vless://UUID@IP_РЕТРАНСЛЯТОРА:443?…&security=tls&sni=vpn.example.com&host=vpn.example.com&type=xhttp&path=%2F<секрет>…
```

## Проверка

1. Без VPN откройте в браузере телефона `https://IP_РЕТРАНСЛЯТОРА`. Должно появиться предупреждение о сертификате (выдан на ваш домен, а не на IP). Это нормально: значит, ретранслятор доходит до основного Caddy.
2. Возьмите новую VLESS-ссылку (переключатель включён), подключитесь в Hiddify или v2RayTun, откройте сайт.
3. На основном сервере в журнале xray появятся подключения с IP ретранслятора:

   ```bash
   cd /opt/fibr/install
   docker compose exec fibr sh -c 'tail -n 5 /data/xray/access.log'
   ```

## Ограничения

- **Реальный IP клиента не виден основному серверу.** Все, кто идёт через ретранслятор, выглядят как один адрес. Лимитер «одна VLESS-ссылка — одно устройство» для них считает все подключения с одного IP, то есть фактически не срабатывает. Статистика WireGuard и AmneziaWG работает как обычно.
- **Мультинода:** ретранслятор пересылает только на основной сервер. Если активна удалённая нода, VLESS и WireGuard выдаются на неё напрямую. AmneziaWG всегда живёт на основном сервере и идёт через ретранслятор.
- **Скорость:** добавляется один «прыжок» Россия → заграница. Обычно это +20–60 мс.
- Российский IP тоже могут заблокировать, но это редкость: блокируют обычно зарубежные хостинги. Если такое случится, поднимите ретранслятор на другом VPS и поменяйте `FIBR_RELAY_HOST`. Пользователям нужно будет заново взять конфиг.
