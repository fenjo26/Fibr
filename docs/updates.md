# Обновление в один клик

Fibr умеет обновляться прямо из админ-панели: суперадмин видит бейдж
«Обновление доступно», жмёт «Обновить» — сервер подтягивает свежий коммит из
GitHub и пересобирает стек. Это **opt-in**: по умолчанию механизм выключен,
потому что он требует доступа к docker-сокету (см. «Безопасность»).

## Зачем

Ручное обновление — это SSH, `git pull` и `docker compose up -d --build`.
Когда серверов несколько или под рукой только телефон, кнопка в панели
короче. Механизм сознательно примитивный: никаких таймеров, автоматических
проверок и автообновлений — обновление запускает человек, когда он этого
хочет.

## Включение

При установке:

```bash
bash install/install.sh --domain vpn.example.com --with-updater
```

На уже установленном сервере — той же командой с флагом (установщик аккуратно
допишет профиль в существующий `.env`) или вручную: добавьте `updater` в
`COMPOSE_PROFILES` в `/opt/fibr/install/.env` (строка должна быть одна!) и
пересоздайте стек:

```bash
docker compose -f /opt/fibr/install/docker-compose.yml up -d
```

Если пользуетесь Xray, строка выглядит так: `COMPOSE_PROFILES=xray,updater`.

Нюанс: установщику, запущенному из чек-аута репозитория с `--with-updater`,
нужна git-история — он сохранит `.git` при копировании в `/opt/fibr`
(обычно она не копируется). Установка `curl | bash` клонирует репозиторий
git-ом, там история есть всегда. Без `.git` (например, репозиторий скачан
zip-архивом) сайдкар ответит ошибкой в статусе, бейдж не появится —
обновляйтесь вручную.

## Как это выглядит

- В верхней панели админки появляется зелёно-синяя пилюля «↻ Обновление
  доступно». Она опрашивается при загрузке и раз в 10 минут; без обновлений
  или при выключенном сайдкаре её нет.
- Клик открывает окно: текущая версия, доступная версия и предупреждение,
  что стек пересоберётся и панели будут недоступны ~1–3 минуты.
- После подтверждения панель пишет «Обновление запущено…», раз в 3 секунды
  проверяет `/api/health` (до 5 минут) и, когда API вернулся, сама
  перезагружает страницу — уже на свежой сборке.

## Что происходит под капотом

1. Панель вызывает `POST /api/admin/updates/apply` (только суперадмин).
2. fibr проксирует запрос в сайдкар `updater` — контейнер с крошечным
   Go-агентом (`server/cmd/fibr-updater`), который отвечает только внутри
   compose-сети на `:8912` и сразу возвращает 202.
3. Агент выполняет в смонтированном чек-ауте (`/opt/fibr` он видит как
   `/repo`):
   ```bash
   git fetch origin
   git reset --hard origin/main
   docker compose -f /repo/install/docker-compose.yml up -d --build
   ```
4. `up -d --build` пересобирает и перезапускает контейнеры. Контейнер fibr
   пересоздаётся — соединение с панелью рвётся, это нормально и ожидается.

**Важно:** `git reset --hard origin/main` затирает локальные правки в
`/opt/fibr` (включая правки файлов прямо на сервере). Данные не страдают —
SQLite-база и ключи лежат в docker-томе `fibr-data`, а не в репозитории.

Ещё один нюанс: `up -d --build` пересобирает и сам сайдкар. Если в новом
коммите изменился его код или `Dockerfile.updater`, команда может оборваться
на собственном пересоздании — к этому моменту всё остальное уже обновлено, а
свежий сайдкар поднимется сам. Если что-то выглядит незавершённым, добейте
вручную: `docker compose -f /opt/fibr/install/docker-compose.yml up -d`.

Одновременно идёт только одно обновление: повторный клик получает 409
«update already in progress».

## Безопасность

- **Порт не публикуется.** Сайдкар доступен только внутри compose-сети; fibr
  ходит на `http://updater:8912` (переопределяется `FIBR_UPDATER_URL` в
  `.env`).
- **Триггер — только суперадмин.** Панель зовёт `/api/admin/updates/apply`
  под админ-токеном; сайдкар из интернета не виден, так что единственная
  дверь — через fibr.
- **Но: docker.sock.** Сайдкар монтирует `/var/run/docker.sock`, а это
  фактически root на хосте. Компрометация контейнера fibr (у которого
  сокета нет) не даёт доступа к докеру; компрометация сайдкара — даёт.
  Поэтому механизм opt-in: включайте только на сервере, которому доверяете,
  и не включайте на мультиарендных машинах.
- **Ничего автоматического.** Ни таймеров, ни вебхуков: сайдкар ничего не
  предпринимает сам, только отвечает на запросы fibr.

## Ручной путь (без updater)

Ровно то же самое, своими руками по SSH:

```bash
cd /opt/fibr && git pull && docker compose -f install/docker-compose.yml up -d --build
```

Работает всегда, независимо от профиля `updater`, и не требует docker.sock
нигде, кроме хоста.

## FAQ

**Бейдж не появляется, хотя обновление есть.**
Либо профиль `updater` не включён (`docker compose ps` должен показывать
контейнер `fibr-updater-1`), либо у чек-аута нет `.git` — статус ответит
ошибкой, панель её молча съест. Посмотреть глазами:
`docker compose -f /opt/fibr/install/docker-compose.yml logs updater`.

**«Доступна» показывает тег, а не коммит — откуда?**
Из GitHub Releases (`releases/latest`): тег удобнее читать, чем хеш. Если
GitHub недоступен, остаётся сравнение коммитов — бейдж покажет первые
символы `remote_sha`.

**Обновление упало на полпути, что теперь?**
Логи: `docker compose -f /opt/fibr/install/docker-compose.yml logs -f
updater`. Чаще всего это сеть при `git fetch` — просто нажмите кнопку ещё
раз. Стек при этом живёт на старой сборке: `reset --hard` и пересборка
идут строго по порядку.

**Можно ли выключить потом?**
Уберите `updater` из `COMPOSE_PROFILES` и выполните
`docker compose -f /opt/fibr/install/docker-compose.yml up -d` — сайдкар
остановится и больше не запустится. Бейдж в панели исчезнет сам.
