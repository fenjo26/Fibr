# FAQ

## Почему скорость ниже тарифа VPS?

WireGuard в Fibr работает в ядре Linux (интерфейс `wg0` через wgctrl) — сам
туннель почти не ест процессор, узким местом обычно не он. Типичные причины
просадки:

- **Канал и маршрут VPS** — тариф «1 Гбит/с» не гарантирует 1 Гбит/с до
  вашего провайдера; расстояние и пиринг влияют сильнее всего. Сравните
  скорость до VPS напрямую (`iperf3` в обе стороны) и через туннель.
- **Процессор VPS** — нагрузка шифрования на 1 vCPU может стать лимитом на
  скоростях в сотни мегабит; посмотрите `top` на сервере во время теста.
- **MTU и фрагментация.** В конфигах Fibr `MTU = 1420` — стандартное
  значение, учитывающее накладные расходы WireGuard и внешних туннелей
  провайдера. Если у вас нетипичная сеть (PPPoE, двойной NAT, мобильный
  оператор), попробуйте 1380–1400: поменяйте `FIBR_MTU` в
  `/opt/fibr/install/.env`, перезапустите контейнеры и скачайте конфиги
  заново — MTU прошивается и в клиентские конфиги.
- **Wi-Fi на клиенте** — частый бытовой лимит; проверьте по кабелю.

## Как сменить порт WireGuard?

Порт вшит в клиентские конфиги (`Endpoint = домен:порт`), поэтому после
смены устройствам нужно скачать конфиг заново.

1. Поменяйте порт в `/opt/fibr/install/.env`:

   ```bash
   nano /opt/fibr/install/.env   # FIBR_WG_PORT=51821
   ```

   Или перезапустите установщик — он аккуратно перенесёт новый порт
   (и домен) в существующий `.env`, не трогая секреты, и откроет порт в
   `ufw`, если тот активен:

   ```bash
   bash /opt/fibr/install/install.sh --domain vpn.example.com --port 51821
   ```

2. Если шли вручную — пересоздайте контейнеры (порт публикации тоже берётся
   из `FIBR_WG_PORT`) и откройте UDP-порт:

   ```bash
   docker compose -f /opt/fibr/install/docker-compose.yml up -d
   ufw allow 51821/udp
   ```

3. Пользователям — обновить конфиги: в Mini App нажать «Конфиг»/«QR-код»
   заново и переимпортировать туннель.

## Как обновить Fibr?

Данные живут в docker volume и при обновении не затрагиваются:

```bash
cd /opt/fibr
git pull
docker compose -f install/docker-compose.yml up -d --build
```

То же самое делает и повторный запуск установщика
(`bash install/install.sh --domain vpn.example.com`): он сохранит
существующий `.env` и пересоберёт контейнеры. Проверить, что всё живо:

```bash
docker compose -f /opt/fibr/install/docker-compose.yml ps
docker compose -f /opt/fibr/install/docker-compose.yml logs -f fibr
```

## Как перенести Fibr на новый сервер?

Всё состояние — БД SQLite (`fibr.db`: пользователи, устройства, ключи,
включая приватный ключ сервера WireGuard) — лежит в docker volume
`fibr-data` (в контейнере — `/data`). Без этого тома сервер сгенерирует
новый ключ и базу: **все устройства придётся создавать заново и
пересканировать QR**.

Порядок переноса:

```bash
# 1. На старом сервере: остановить и забрать данные тома
docker compose -f /opt/fibr/install/docker-compose.yml down
tar -C /var/lib/docker/volumes/fibr_fibr-data/_data \
    -czf fibr-data.tar.gz .
# имя тома проверьте: docker volume ls | grep fibr

# 2. Скопировать архив на новый сервер
scp fibr-data.tar.gz root@newserver:/root/

# 3. На новом сервере: установить Fibr тем же доменом (install.sh),
#    остановить и подменить содержимое тома
docker compose -f /opt/fibr/install/docker-compose.yml down
tar -C /var/lib/docker/volumes/fibr_fibr-data/_data \
    -xzf /root/fibr-data.tar.gz
docker compose -f /opt/fibr/install/docker-compose.yml up -d
```

После подъёма устройства подключатся к новому серверу сами — их конфиги
(ключи, endpoint) не меняются, если домен и порт прежние. Клиенты WireGuard
переподключатся по keepalive.

## Забыл админ-токен

Токен всегда лежит в `.env` на сервере:

```bash
grep FIBR_ADMIN_TOKEN /opt/fibr/install/.env
```

Сгенерировать новый: добавьте `--force` к установщику (перегенерирует и
`FIBR_SECRET` — все сессии Mini App при этом истекут, пользователи просто
зайдут заново).

## Безопасность: приватные ключи хранятся на сервере

Чтобы админка и Mini App могли показать QR-код, приватные ключи устройств
(и сервера) хранятся на сервере — в SQLite внутри тома `fibr-data`. Это
означает:

- **компрометация VPS = компрометация ключей** — злоумышленник с доступом
  к серверу может читать трафик-метаданные и выдавать себя за клиентов;
  ставьте Fibr только на сервер, которому доверяете;
- закрывайте SSH (ключи, fail2ban), `FIBR_ADMIN_TOKEN` — это полный доступ
  к панели, не публикуйте его;
- наружу смотрят только порты 80/443 (Caddy) и UDP WireGuard — API
  работает за Caddy и напрямую не опубликован;
- если ключи хранить на сервере нельзя — Fibr в текущем виде не подходит,
  генерируйте конфиги wg-quick самостоятельно.

Ещё два момента из этой же серии:

- **Отключённый пользователь** не может войти в Mini App, но его уже
  выданные пиры продолжают работать. Заблокировали человека — отключите
  его устройства (или удалите пользователя): отключение устройства удаляет
  пира из `wg0`, и сеанс рвётся сразу.
- **Отданные конфиги не отзываются сами.** Удаление устройства в панели
  прекращает доступ, но файл `.conf`, скачанный ранее, продолжает
  содержать ключи этого устройства — они просто перестают приниматься
  сервером.

## Где все настройки сервера?

Рабочий файл — `/opt/fibr/install/.env` (правки + `docker compose up -d`).
Шпаргалка по переменным:

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `FIBR_DOMAIN` | — | публичный домен; он же endpoint в конфигах, если не задан `FIBR_WG_HOST` |
| `FIBR_WG_PORT` | `51820` | UDP-порт WireGuard (и порт публикации контейнера) |
| `FIBR_WG_HOST` | = `FIBR_DOMAIN` | отдельный хост endpoint для клиентских конфигов (например, IP вместо домена) |
| `FIBR_SUBNET` | `10.8.0.0/24` | подсеть туннеля (только IPv4 /24); адрес сервера — `.1` |
| `FIBR_DNS` | `1.1.1.1,1.0.0.1` | DNS, прошиваемый в клиентские конфиги |
| `FIBR_MTU` | `1420` | MTU туннеля (сервер и клиенты) |
| `FIBR_MAX_DEVICES` | `10` | лимит устройств на пользователя |
| `FIBR_STATS_INTERVAL` | `30s` | период сбора счётчиков трафика |
| `FIBR_TELEGRAM_BOT_TOKEN` | — | токен бота из BotFather |
| `FIBR_ADMIN_TELEGRAM_IDS` | — | Telegram ID, получающие роль админа (через запятую) |
