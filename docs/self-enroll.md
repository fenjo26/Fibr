# Self-enroll: регистрация по приглашениям (этап 4)

По умолчанию Fibr открыт: любой, кто открыл Mini App из бота, автоматически
регистрируется и может создать себе устройство. Режим приглашений закрывает
эту дверь — новый человек попадает в систему только по одноразовой
ссылке-приглашению, которую сгенерировал админ.

## Зачем это нужно

- вы раздаёте VPN узкому кругу (семья, команда) и не хотите, что любой
  знакомый знакомого «просто зашёл и пользуется»;
- каждое устройство занимает адрес в /24-подсети и полосу сервера —
  приглашения дают явный контроль над тем, кто её ест;
- в списке приглашений видно, кто и когда воспользовался ссылкой, —
  простая бухгалтерия доступа.

## Включение режима

В `/opt/fibr/install/.env` добавьте:

```
FIBR_REQUIRE_INVITE=true
```

и перезапустите контейнер:

```bash
docker compose -f /opt/fibr/install/docker-compose.yml up -d
```

- `true` — новые пользователи обязаны предъявить валидный неиспользованный
  код приглашения;
- `false` (по умолчанию, переменной может не быть) — текущее поведение:
  свободная авторегистрация при первом входе через Mini App.

Уже зарегистрированные пользователи входят как обычно — приглашение нужно
только один раз, при создании аккаунта. Админы из `FIBR_ADMIN_TELEGRAM_IDS`
при первом входе тоже проходят через приглашение (создайте его заранее).

## Генерация приглашения

Админ-панель → вкладка **Пользователи** → блок **Приглашения**:

1. впишите заметку (необязательно) — например, «ссылка для Пети»;
2. нажмите «Создать приглашение» — ссылка сразу копируется в буфер;
3. отправьте ссылку человеку любым удобным способом.

Таблица показывает: код, ссылку (клик — скопировать), заметку, когда создано
и кем использовано (или «не использовано»). Кнопка «Удалить» убирает
приглашение, которым ещё не воспользовались; удаление уже использованного
также разрешено — на созданный аккаунт это не влияет.

## Формат ссылки

```
https://<ваш-домен>/miniapp/?invite=CODE
```

`CODE` — 10 символов из алфавита без похожих знаков (`0/O/o`, `1/l/I/i`
исключены), например `wPdF85d96e`. Код одноразовый: ровно одна регистрация,
потом `invalid invite`.

В dev-режиме (без домена) панель показывает относительный путь
`/miniapp/?invite=CODE`.

## Как передать код через Telegram

Mini App принимает код двумя способами:

1. **Прямая ссылка** (проще всего): отправьте человеку
   `https://vpn.example.com/miniapp/?invite=CODE` — Telegram откроет Mini App,
   код возьмётся из URL-параметра `?invite=`.

2. **Deep-link с startapp**: отправьте ссылку вида
   ```
   https://t.me/<имя_бота>?startapp=CODE
   ```
   (или `<имя_бота>?startapp=CODE` — Telegram сам превратит это в кнопку).
   При открытии Mini App код придёт в `Telegram.WebApp.initDataUnsafe.start_param`.

Оба способа равнозначны; deep-link удобен, когда хочется короткую ссылку на
бота, а не на домен панели.

Что происходит у получателя:

- человек открывает ссылку → Mini App отправляет `invite_code` вместе с
  подписанным Telegram-данными на `POST /api/auth/telegram`;
- сервер проверяет подпись, создаёт аккаунт и помечает код использованным;
- дальше — обычный флоу: добавить устройство, отсканировать QR.

Если человек откроет бота без приглашения (или код уже потрачен), Mini App
покажет сообщение «Регистрация только по приглашению».

## Поведение при выключенном режиме

`FIBR_REQUIRE_INVITE=false` (или переменная не задана):

- авторегистрация свободная — как раньше;
- блок «Приглашения» в панели работает, ссылки можно создавать, но код в
  запросе просто игнорируется (поля `invite_code` можно не слать);
- уже созданные приглашения ни к чему не обязывают и не «сгорают».

## API (для скриптов и интеграций)

| Endpoint | Описание |
|---|---|
| `GET /api/admin/invites` | список: code, note, created_at, created_by, used_by, used_at, username использовавшего, link |
| `POST /api/admin/invites` | создать: тело `{"note": "..."}` (note необязательна); ответ `{code, link, ...}` |
| `DELETE /api/admin/invites/{code}` | удалить приглашение (204) |
| `POST /api/auth/telegram` | теперь принимает `invite_code` рядом с `init_data`; при включённом режиме без кода — 403 `invite required`, с потраченным/чужим кодом — 403 `invalid invite` |

Bearer-токен — админ-токен или сессия пользователя с ролью admin.
