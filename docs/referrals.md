# Реферальная программа: два уровня комиссий

Каждый аккаунт Fibr получает постоянный **реферальный код** и ссылку.
Пришедшие по ней регистрируются с атрибуцией («кто кого пригласил»), а
суперадмин в панели фиксирует **пополнения** — одним действием продлевается
подписка и автоматически начисляются комиссии: **15% прямому пригласившему
(L1)** и **5% тому, кто пригласил пригласившего (L2)**. Проценты, валюта и
контакты настраиваются суперадмином. Заработок копится на балансе и
выплачивается вручную — деньги, как и в [billing.md](billing.md), ходят вне
системы (крипта, перевод), Fibr ведёт только честный учёт.

## Модель

- `users.referral_code` — постоянный 8-символьный код, выдаётся при создании
  аккаунта (существующим базам — backfill'ом при первом старте после
  обновления).
- `users.referred_by` — чей код предъявлен при регистрации; `NULL` = пришёл
  сам. Это **не** `owner_id`: owner — реселлер, создавший аккаунт вручную;
  referred_by — самостоятельная регистрация по чужой ссылке.
- `payments` — журнал пополнений: сумма (в копейках), дни подписки, заметка,
  кто записал.
- `referral_earnings` — комиссии: бенефициар, платёжщик, уровень (1|2),
  сумма.
- `referral_payouts` — выплаты суперадмином; баланс = начислено − выплачено.

Суммы хранятся в **минорных единицах** (копейках) как `INTEGER` — без float.
Начисление бессрочное: с каждого пополнения приведённого клиента, пока он
платит. Отключение программы (`referral_enabled=0`) прекращает новые
начисления, но атрибуция и история остаются.

## Ссылки и вход

Форматы одной и той же ссылки:

- веб (основной, сайт — первичная дверь): `https://<домен>/cabinet/?ref=CODE`
  — кабинет сохраняет код и атрибутирует регистрацию;
- deep-link Telegram: `t.me/<бот>?startapp=ref_CODE` — Mini App отправляет
  `start_param` с префиксом `ref_` как `referral_code`;
- бот: `t.me/<бот>?start=ref_CODE` — бот парсит payload `/start`, атрибуция
  засчитывается при первом сообщении, кнопка приложения ведёт на `?ref=CODE`.

В кабинете секция показывает **обе** ссылки: веб — первой, Telegram — второй
(у каждой своя кнопка копирования); `/api/me/referrals` отдаёт их полями
`web_link` и `tg_link`.

При регистрации код резолвится один раз и навсегда: неизвестный или
отключённый код игнорируется (регистрация не блокируется). В режиме
`FIBR_REQUIRE_INVITE=true` **валидный реф-код заменяет приглашение** — иначе
реферальная ссылка не имела бы смысла в invite-only инсталляции.
Самоприглашение невозможно (кода нового юзера ещё не существует).

## Пополнение: одна кнопка вместо трёх

Панель → **Пользователи** → колонка «Действует до» → **«Пополнить»**: сумма,
дни подписки (по умолчанию 30, 0 = без продления), заметка. Сервер в одной
транзакции:

1. пишет строку в `payments`;
2. продлевает `expires_at` (база — `max(сейчас, текущий срок)`, та же
   арифметика, что у «+30 дн»);
3. начисляет L1 рефереру платящего и L2 — его пригласившему (проценты из
   настроек на момент платежа; округление вниз до копейки).

Если срок двинулся — пиры WG/xray пересобираются сразу, как у `PATCH
expires_at`.

## Что видит каждый

- **Пользователь** (Mini App и кабинет, секция «Реферальная программа»): свой
  код и две ссылки с кнопками копирования (веб — первой, Telegram — второй),
  условия, плитки «Приглашено /
  Заработано / Выплачено / Баланс», список приглашённых с заработком по
  каждому и контакты для вывода. Секция скрыта при выключенной программе.
- **Суперадмин**, панель → **Рефералы**: таблица «кто кого привёл» с
  балансами и кнопкой **«Выплатить»** (сумма не больше баланса), журнал
  выплат и журнал пополнений. В таблице пользователей — колонка
  **«Пришёл от»**.
- **Бот**: команда `/ref` показывает код и ссылку; `/help` упоминает её.
- Экран «Подписка истекла» дополнительно показывает контакты суперадмина из
  настроек (и публично в `GET /api/public/info`) — юзер сразу видит, кому
  платить.

## Настройки

Панель → **Настройки** (суперадмин), хранятся в `settings`:

| Ключ | По умолчанию | Что задаёт |
|---|---|---|
| `referral_enabled` | `1` | вкл/выкл программы (новые начисления) |
| `referral_percent_l1` | `15` | % прямому пригласившему, 0–100 |
| `referral_percent_l2` | `5` | % пригласившему пригласившего, 0–100 |
| `currency` | пусто | суффикс сумм («₽», «USDT») |
| `contact_info` | пусто | многострочные контакты для юзеров (продление, вывод) |

## API

| Метод и путь | Кто | Что |
|---|---|---|
| `POST /api/auth/telegram` c `referral_code` | все | регистрация с атрибуцией |
| `GET /api/me/referrals` | юзер | код, ссылки (`web_link`, `tg_link`), условия, статистика, приглашённые, контакты |
| `POST /api/admin/users/{id}/payments` `{amount, days, note}` | суперадмин | пополнение + продление + комиссии |
| `GET /api/admin/payments` | суперадмин | журнал пополнений |
| `GET /api/admin/referrals` | суперадмин | обзор «кто кого» + настройки + выплаты |
| `POST /api/admin/referrals/payouts` `{user_id, amount, note}` | суперадмин | отметить выплату (409 при сумме больше баланса) |
| `GET/PATCH /api/admin/settings` | суперадмин | настройки программы |
| `GET /api/public/info` | все | + `contact_info` |

`amount` везде — минорные единицы (`500.50 ₽` = `50050`); фронтенды
конвертируют (`Fibr.toMinor` / `Fibr.fmtMoney` в `/shared/app.js`).
`GET /api/admin/users` отдаёт `referred_by_name` для колонки атрибуции.

## FAQ

**Юзер зарегистрировался по ссылке, но комиссий нет.**
Комиссия возникает только с **пополнений**, а не с факта регистрации.
Пополнение записывает суперадмин кнопкой «Пополнить» (или POST-ом). «+30 дн»
без суммы — просто продление, комиссий не создаёт.

**Почему комиссия 74.99, а не 75.00?**
Начисление — `amount × percent / 100` с округлением вниз до целой копейки
(`499.97 × 15% = 7499.55 → 7499`). В минорных единицах всегда INTEGER.

**Можно ли выплатить больше баланса?**
Нет — 409 `insufficient referral balance`. Корректировки сверх баланса
делайте новыми начислениями, а не овердрафтом.

**Платящий сам себе реферер?**
Нет: `referred_by` фиксируется один раз при создании аккаунта, свой код
предъявить нельзя (аккаунта ещё нет), циклы в цепочке исключены.

**Что с юзером под админом-реселлером?**
`owner_id` и `referred_by` независимы. Реселлер не участвует в реферке
автоматически: комиссии идут только по `referred_by`. Реселлер может быть
участником программы наравне со всеми — у него тоже есть код и баланс.

**Выключил программу — балансы сгорели?**
Нет: `referral_enabled=0` останавливает только новые начисления. Балансы,
выплаты и атрибуция сохраняются; выплачивать остатки можно и после
выключения.

**Админ-реселлер может записать пополнение?**
Нет: все денежные эндпоинты (`payments`, `payouts`, `settings`) — только
суперадмин, как и каждая запись `expires_at` (см. [billing.md](billing.md),
[roles.md](roles.md)).
