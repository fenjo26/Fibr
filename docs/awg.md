# AmneziaWG — обфусцированный WireGuard

Обычный WireGuard быстр и встроен в ядро, но его пакеты легко распознаются
системами анализа трафика (DPI): фиксированные «магические» байты в начале
пакета, предсказуемый размер рукопожатия. В сетях с активной фильтрацией
(общественный Wi-Fi, корпоративные сети, некоторые страны) такой трафик
блокируют.

AmneziaWG (AWG) расширяет WireGuard обфускацией на уровне протокола:

- **Jc** — перед каждым рукопожатием посылается несколько (Jc) мусорных
  пакетов случайного размера от **Jmin** до **Jmax**;
- **S1 / S2** — дополнение (padding) пакетов инициации и ответа рукопожатия;
- **H1–H4** — случайные значения вместо стандартных «магических» байтов
  заголовка.

Для DPI такой поток выглядит как бессмысленный UDP-шум, а не WireGuard.

## AWG 2.0 (по умолчанию)

Параметры AmneziaWG 1.0 (фиксированные H1–H4, только S1/S2) в России с 2025
года распознаются ТСПУ. Поэтому Fibr выдаёт конфиги **AWG 2.0**:

- **S3 / S4** — добавочное дополнение пакетов cookie и транспортных пакетов
  (размеры больше не совпадают с WireGuard);
- **H1–H4 — диапазоны** (`H1 = 26777853-94850946`): каждый пакет получает
  новый случайный заголовок из своего диапазона, диапазоны не пересекаются;
- **I1** — «сигнатурный» пакет перед каждым рукопожатием. Fibr делает его
  похожим на QUIC Initial (1200 байт: заголовок QUIC v1, случайный
  connection id и «зашифрованная» нагрузка). Это параметр только клиента,
  свой можно задать в `FIBR_AWG_I1` — существующие конфиги от этого не
  ломаются;
- MTU туннеля AWG 2.0 — 1376 (как у AmneziaVPN по умолчанию): S4 и I1
  занимают место в пакете.

Демон на сервере — `amneziawg-go` v3.1. Совместимость проверена
сквозным тестом: туннель AWG 2.0 между v3.1 и v0.2.19 работает в обе
стороны (то есть и со старыми, и с новыми приложениями Amnezia).

Клиенты: **AmneziaVPN** (iOS / Android / ПК) и **AmneziaWG** последних версий
— обновите приложение перед импортом. Импорт на iPhone: самый надёжный путь
— QR-код из кабинета; файл `.conf` из Telegram сначала «Сохранить в Файлы»,
потом в AmneziaVPN → «+» → «Файл».

**Важно при обновлении сервера:** переход на 2.0 генерирует новый набор
параметров (`awg2_params` в таблице settings), поэтому **все AmneziaWG-
устройства должны заново скачать конфиг/QR** — старые 1.0-конфиги больше не
подключатся. Вернуть старое поведение: `FIBR_AWG_VERSION=1` (старые
параметры `awg_params` хранятся рядом и не меняются).

## AmneziaWG как протокол устройства (по умолчанию)

Теперь AmneziaWG — **третий протокол на выбор** рядом с WireGuard и VLESS:
при создании устройства в кабинете / Mini App / админке выберите
«AmneziaWG», в боте — команда `/amnezia`. Включено по умолчанию.

Сервер поднимает для этого **второй туннель** `awg0` (демон
`amneziawg-go` уже в образе) рядом с обычным `wg0`:

| | WireGuard | AmneziaWG |
|---|---|---|
| Интерфейс | `wg0` | `awg0` |
| Порт (UDP) | `FIBR_WG_PORT` (51820) | `FIBR_AWG_PORT` (51821) |
| Подсеть | `FIBR_SUBNET` (10.8.0.0/24) | `FIBR_AWG_SUBNET` (10.9.0.0/24) |
| Клиенты | WireGuard, AmneziaVPN, Fibr | только AmneziaVPN |

Откройте в файрволе `51821/udp` (`install.sh` делает это для ufw).
Выключить: `FIBR_AWG_ENABLED=false`. Если весь сервер уже работает в
режиме `FIBR_WG_ENGINE=awg` (см. ниже), второй туннель не поднимается.
AmneziaWG-устройства обслуживает только этот сервер (ноды мультинода
раздают обычный WireGuard). Если второй туннель не смог стартовать,
WireGuard продолжает работать, а пункт AmneziaWG показывается выключенным.

## AWG или Xray?

У Fibr два механизма устойчивости к DPI — они решают разные задачи:

| | AmneziaWG | Xray (VLESS + Reality) |
|---|---|---|
| Что это | WireGuard с обфускацией | прокси, маскирующийся под HTTPS к крупному сайту |
| Транспорт | UDP | TCP |
| Скорость | выше (ядро WireGuard-семантики) | ниже (проксирование TLS) |
| Выбор | протокол **отдельного устройства** (второй туннель) или режим всего сервера | протокол **отдельного устройства** |
| Статистика в панели | полная (как у WG) | нет (нули) |
| Клиенты | AmneziaVPN | v2rayNG, Hiddify, Streisand и т.п. |

Нельзя смешивать: на одном сервере AWG-режим заменяет обычный WireGuard для
всех устройств (параметры обфускации принадлежат интерфейсу). Нужен и
обычный WG, и защита от DPI — используйте Xray как второй протокол устройства,
а сервер оставьте на kernel-движке.

## Включение

При установке:

```bash
bash install/install.sh --domain vpn.example.com --awg
```

На уже работающем сервере — в `/opt/fibr/install/.env`:

1. `FIBR_WG_ENGINE=awg`
2. `docker compose up -d` (пересобирать образ не нужно — демон
   amneziawg-go уже входит в образ fibr)

Порт и файрвол не меняются: AWG работает на том же UDP-порту
`FIBR_WG_PORT`. Параметры обфускации (Jc, Jmin, Jmax, S1, S2, H1–H4)
генерируются сервером один раз, при первом старте в awg-режиме, и хранятся
в базе — вручную их задавать не нужно.

Как это устроено внутри: контейнер fibr запускает userspace-демон
`amneziawg-go` v3 (форк wireguard-go) дочерним процессом; демон создаёт
TUN-интерфейс `wg0`, а сервер настраивает его через UAPI-сокет (тот же
wireguard-wgctrl-механизм, что и для ядерного WireGuard). Конфиг-файла у
демона нет.

## Клиенты

QR-коды и текстовые конфиги устройств в awg-режиме содержат блок
параметров `Jc/Jmin/Jmax/S1–S4/H1–H4/I1` в секции `[Interface]`. Такой конфиг
понимают только приложения **AmneziaVPN**:

- **Android / iOS:** Amnezia VPN (Google Play, App Store, F-Droid)
- **Windows / macOS / Linux:** Amnezia VPN Desktop
  (https://docs.amnezia.org/ru/downloads)

**Официальное приложение WireGuard такой конфиг не импортирует** — оно не
знает поля `Jc` и остальные. Существующие обычные WireGuard-устройства
после переключения сервера в awg-режим нужно пересоздать: старые QR больше
не подойдут (рукопожатие не пройдёт без параметров обфускации).

Импорт: в AmneziaVPN → добавить соединение → «Файл» или «QR-код» — конфиг
Fibr выглядит для приложения как родной awg-конфиг.

## Ограничения

- **Движок — на весь сервер**: переключение `FIBR_WG_ENGINE` меняет
  поведение интерфейса wg0 целиком; часть устройств на обычном WG, часть на
  AWG — нельзя (так устроена и сама Amnezia: параметры интерфейсные).
- **Только клиенты AmneziaVPN** — официальный WireGuard (и роутеры с
  заводским WG: Keenetic, OpenWrt без awg-пакетов) не подойдёт.
- **Userspace-демон**: в awg-режиме трафик шифруется процессом
  amneziawg-go, а не модулем ядра — пропускная способность несколько ниже
  ядерного WireGuard (для типичного VPS некритично).
- **Параметры фиксируются навсегда**: S1/S2/H1–H4 должны совпадать на
  сервере и клиентах, поэтому после первого запуска сервер хранит их в базе
  и никогда не меняет. Сменить можно только вручную (settings-таблица,
  ключ `awg_params`) с перевыпуском всех конфигов.
