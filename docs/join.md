# Quick-connect: коды быстрого подключения

Код quick-connect — короткий одноразовый код привязанный к конкретному
устройству. Владелец генерирует его в Mini App (админ — в панели или для
устройства из своего subtree), человек вводит код в клиенте Fibr — и
получает готовый конфиг. Один и тот же механизм работает на телефоне,
ПК и телевизоре: где-то удобнее отсканировать QR, где-то ввести 8 символов
с пульта.

Это отличается от [приглашений](self-enroll.md): invite создаёт **аккаунт**
новому человеку, join-код лишь **доставляет конфиг** уже существующего
устройства и ничего не аутентифицирует.

## Как это выглядит

1. Владелец устройства жмёт «Код» рядом с QR в Mini App.
2. Сервер генерирует код из 8 символов (алфавит без похожих `0/O/1/l`) с
   временем жизни `FIBR_JOIN_TTL` (по умолчанию 15 минут) и отдаёт:
   - сам код — для ручного ввода в клиенте («Добавить тоннель» → «По коду»);
   - ссылку `https://<domain>/join/<code>` — её можно переслать;
   - QR со ссылкой — камера телефона откроет страницу, клиент Fibr
     распознаёт её сразу.
3. Клиент обменивает код: `POST /api/join/{code}` → `{name, protocol,
   config}` — и импортирует конфиг. Код гасится атомарно: даже при гонке
   запросов победит ровно один.
4. Страница `https://<domain>/join/<code>` показывает код и кнопку
   «Открыть в приложении» (`fibr://join/<base64 url>`). Она **не гасит**
   код — превью ссылок в мессенджерах безвредны.

## Поведение

| Ситуация | Ответ `POST /api/join/{code}` |
|---|---|
| корректный неиспользованный код | 200 + конфиг |
| код уже обменян или истёк TTL | 410 `code already used or expired` |
| такого кода нет | 404 (код не палится) |
| подписка владельца устройства истекла | 403 `subscription expired` |
| аккаунт владельца отключён / устройство выключено | 403 |

Погашенный код остаётся погашенным при любом исходе обмена после него:
сначала атомарный `UPDATE`, потом проверки и рендер. При удалении
устройства его коды удаляются каскадом (FK), использованные и просроченные
коды подчищаются лениво при следующей генерации.

## Эндпоинты

- `POST /api/me/devices/{id}/join` — свой код (Bearer сессии Mini App);
- `POST /api/admin/devices/{id}/join` — админ: устройство из своего
  subtree, чужое читается как 404 (см. [roles](roles.md));
- `POST /api/join/{code}` — публичный обмен кода на конфиг;
- `GET /join/{code}` — публичная страница-лендинг (не гасит код).

## Конфигурация

```
FIBR_JOIN_TTL=15m   # время жизни кода; положительная длительность
```

Xray-устройства тоже поддерживаются: обмен вернёт `vless://`-ссылку в поле
`config` (клиент Fibr её пока не импортирует — ссылка для v2rayNG/Hiddify,
полезно вручную со страницы `/join`).

## Безопасность

- 8 символов из 53-символьного алфавита ≈ 6.2e13 комбинаций на окно в
  15 минут — перебор через публичный эндпоинт нереален (и не отличим от
  404 до первой удачи).
- Код даёт только конфиг устройства — те же данные, что QR в Mini App.
  Приватный ключ покидает сервер ровно один раз, владельцу кода.
- Код не аутентифицирует: доступ к аккаунту, статистике и управлению он
  не даёт.
